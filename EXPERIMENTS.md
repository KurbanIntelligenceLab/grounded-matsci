# Experiment guide

Every experiment is a subcommand of the `grounded-matsci` CLI, driven by a versioned YAML
config under `configs/`:

```bash
uv run grounded-matsci <subcommand> --config configs/<name>.yaml
```

This page maps each subcommand to what it measures, what drives it, and which committed
result under `results/` it reproduces. Read it before reading the code — several modules
assume the vocabulary defined at the bottom of this page.

## The verifier

A claim is checked by the cheapest tier that could falsify it, escalating only if it
survives and carries a quantitative assertion worth confirming
(`verification/verify.py`, `verification/ground.py`):

| Tier | Check | Reference | Cost |
|---|---|---|---|
| 0 | syntactic | RDKit sanitization of the SMILES | microseconds |
| 1 | identity | RDKit canonical form; PubChem formula; named-phase space group | milliseconds |
| 1.5 | tabulated | experimental / reference tables (`domain/refdata.py`) | milliseconds |
| 2 | property | accept-either-frame property agreement | seconds |
| 3 | physics | PySCF DFT (dipole, gap) | seconds to minutes |

Each verifier returns one of `ok`, `fail`, `warn`, `unchecked`. Tolerances are set in one
place, `domain/tolerances.py`.

## The conditions

The study contrasts five conditions over the same frozen prompt corpus. The first is the
control; the rest are interventions.

1. **Unguarded baseline** — the model answers with no verification (`harness`).
2. **Self-critique** — the model is asked to check its own answer, with no tools
   (`loop.run_self_critique`).
3. **RAG-in-prompt** — the relevant reference fact is placed in the prompt up front,
   whether or not the model would have erred (`loop.run_rag_in_prompt`).
4. **Mode A, tool-interleaved** — every chemical claim is verified as it is produced; any
   failure is injected back as a correction and the model revises, until nothing fails or
   the step budget is spent (`loop.run_mode_a`).
5. **Mode B, generate-and-rerank** — sample N independent reasoning paths, score each with
   the trust metric, and select the best (`loop.run_mode_b`).

Conditions 2 through 5 all run from the single `arms` subcommand.

Filenames under `results/` carry an older `exp1`–`exp4` prefix. Those files are frozen
released artifacts whose SHA-256 hashes are registered in
`data/manifests/results_manifest.yaml` and cited by the manuscript, so they keep their
names; this table is the mapping. The same applies to
`data/frozen/exp4_isotopes_reps45.jsonl`, whose path is recorded inside
`results/isotope_5seed_result.json` as provenance.

Two result sets are regenerated by scripts rather than CLI subcommands, because they are
reanalyses of stored outputs rather than new generation:

```bash
uv run python scripts/run_semantic_entropy.py   # semantic-entropy detector
uv run python scripts/grade_cove.py             # chain-of-verification arm
```

## Generation traces

The raw traces the reported numbers were computed from are committed under `data/traces/`,
hashed in `data/manifests/traces.yaml`. Each row is one (prompt, model, condition,
replicate) cell carrying the model's `final_text` and the in-loop verifier verdicts, so a
reader can re-grade any published number without re-running generation:

```bash
uv run python scripts/audit_tier_shares.py \
  --traces data/traces/holdout_arms_rep0.jsonl \
  --named-sg data/frozen/named_sg_rule_gt.json \
  --ef-lookup data/frozen/ef_lookup.json \
  --pubchem data/frozen/pubchem_cache.json \
  --holdout-gt data/frozen/holdout_ground_truth.json
```

That audit re-grounds the released final answer text. It is not a reproduction of the
reported tier shares, which describe the tiers the verifier exercised in loop during the
run; those per-claim tier events are not among the released artifacts.

Two artifacts are not in the project archive and are listed in
`data/manifests/pending_traces.yaml`: the inline-confidence raw traces, and the per-item
trust/correctness rows that `scripts/audit_calibration.py` consumes.

## Run order

Generation runners are checkpointed and resumable; the analysis steps read those
checkpoints. The intended order is:

1. `harness` — the baseline pass, writing a resumable checkpoint under `outputs/`.
2. `arms` — the four intervention conditions over the same corpus.
3. `selfcheck` and `inline-conf` — the detector baselines.
4. `endtask`, `endtask-derived`, `codata`, `isotopes` — propagation and transfer domains.
5. `two-stage-triage`, `gated-constants`, `small-models` — the analyses that build on the
   detector and gate thresholds frozen in step 3.

Every run writes a provenance `manifest.json` next to its outputs under
`outputs/<experiment_id>/`, recording the git SHA, the config hash, and the seed.

Generation subcommands require `OPENROUTER_API_KEY`. `MP_API_KEY` enables the Materials
Project reference tier and degrades gracefully when absent. The regression suite
(`uv run pytest`) is fully offline and needs neither.

## Rarity strata

Prompts are stratified by how well attested the subject is, which is the axis along which
error rates move most. The committed corpus (`data/frozen/corpus_final_v2.json`, 528
prompts) labels each prompt with one of:

| Label in the data | Count | Meaning |
|---|---|---|
| `S1_well_known` | 107 | textbook-familiar subjects |
| `S2_common_specialized` | 94 | common within the field |
| `S3_rare_ambiguous` | 180 | rare or ambiguously named |
| `S4_recent_specialist` | 147 | recent or specialist-only |

The manuscript renames these strata R1–R4 to avoid colliding with its supplementary note
numbering; the data files keep the `S`-prefixed labels above.

## Registration hashes

Several modules and manifests carry short SHA-256 prefixes — the extractor `42e03ae2`,
the verifier configuration `6e45797a`, the corpus `66365980`, the holdout ground truth
`5e80c788`. These are freeze markers: the content hash of each artifact was recorded
before the holdout was run, so that the scientific contract could not be adjusted after
seeing the results. Comments naming them mark code that is under that freeze. The
registration record itself is kept in the project's private records and is not
distributed with this repository.
